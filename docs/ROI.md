# ROI: окупаемость внедрения OfferDesk

## Контекст

Компания «Дом-Мастер» — строительство домов ИЖС. Отдел продаж: **5 менеджеров**. Средний чек сделки: **8 млн ₽**. Маржа: **15%** (= 1.2 млн ₽ с одной сделки).

## Проблема (baseline)

- **30–40% лидов теряются** из-за медленной реакции (норма — 15 мин, факт — часы).
- **40–60 минут** на подготовку одного КП вручную.
- **Regex-парсер теряет ключевые поля**: `budget_rub` recall 0.00, `start_date` recall 0.30, `financing` recall 0.50 (по golden set из 15 звонков).
- **Нет контроля качества**: непонятно, какие поля заполнены достоверно, какие — заглушки.

## Затраты на внедрение

| Статья | Стоимость |
|---|---|
| Разработка (пилот + настройка под эталон) | 1 разово (фикс) |
| OpenAI API (gpt-4o-mini, ~5K токенов/сделка) | ~15–30 ₽/сделка |
| VPS + Docker (Waitress + systemd) | ~700 ₽/мес |
| Обучение менеджеров | 1 день |
| **Итого подписка** | **30–50 тыс. ₽/мес** |

## Экономия

### 1. Высвобождение времени менеджеров

5 менеджеров × 20 КП/мес × 50 мин = **~83 часа/мес**.

При ставке 500 ₽/час = **41 500 ₽/мес** прямого высвобождения.

### 2. Рост конверсии из лида в замер

- Быстрая реакция (5 мин вместо часов) даёт **+10–15%** конверсии.
- Из 100 лидов: +10–15 замеров.
- Из 15 замеров: +1–2 сделки/мес × 1.2 млн ₽ маржи = **+1.2–2.4 млн ₽/мес**.

## Окупаемость

| Сценарий | Экономия/мес | Затраты/мес | Окупаемость |
|---|---|---|---|
| Пессимистичный (только высвобождение времени) | 41 500 ₽ | 30 000 ₽ | **~1 месяц** |
| Базовый (высвобождение + 1 доп. сделка) | 1.24 млн ₽ | 40 000 ₽ | **~1 неделя** |
| Оптимистичный (высвобождение + 2 доп. сделки) | 2.44 млн ₽ | 50 000 ₽ | **~3 дня** |

**Вывод:** при среднем чеке 8 млн ₽ и марже 15% внедрение окупается **за первый месяц**, а с учётом роста конверсии — **за первую неделю**.

## Ограничения и риски

- **Качество транскрибации** влияет на точность извлечения. Шум, диалекты, плохая связь -> ошибки.
- **Юридическая ответственность** за КП остаётся на менеджере. Схема «черновик -> утверждение» не случайна: LLM не принимает решение о цене.
- **LLM не решает цену** — только извлекает и структурирует. Ценообразование — по прайсу компании.
- **Нет интеграции с 1С / Битрикс24** в текущей версии. В roadmap (см. `docs/DOCUMENTATION.md`).
- **Зависимость от прокси** для доступа к OpenAI API. При недоступности — regex fallback (проверено, 53.3% exact etalon_score).
- **Прокси OpenAI недоступен на момент сдачи.** LLM-метрики в roadmap; baseline regex честно измерен.

## Что НЕ входит в ROI

- Затраты на изменение бизнес-процессов компании (переобучение, регламенты).
- Затраты на интеграцию с внешними системами (1С, Битрикс24) — обсуждается отдельно.
- Юридическая экспертиза КП — остаётся за клиентом.

## Roadmap

1. **LLM-метрики v1 vs v2** — когда прокси оживёт (готов промпт v2 с 5 few-shot).
2. **Интеграция с Битрикс24 / amoCRM** — выгрузка сделок.
3. **Интеграция с 1С** — актуальные прайс-листы.
4. **Дашборд качества** — precision/recall в реальном времени, распределение A/B/C, % эскалаций.
5. **Мультиканальность** — WhatsApp, Telegram, веб-чат.

## Как считали

- **Средний чек 8 млн ₽** — по данным компании «Дом-Мастер» (тёплый контур 75 000 ₽/м² × ~107 м²).
- **Маржа 15%** — экспертная оценка.
- **5 менеджеров, 20 КП/мес** — типовой отдел продаж ИЖС.
- **+10–15% конверсии** — по отраслевым данным о влиянии скорости реакции на конверсию.

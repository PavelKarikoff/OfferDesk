# Known issues

## Прокси OpenAI недоступен (2026-09-28) — решено (2026-09-30)

**Симптом:** `OPENAI_PROXY=http://193.233.174.4:8888` →
`openai.APIConnectionError: Connection reset by peer`.

**Диагностика (2026-09-28):**
- NL-Proxy (5.129.213.88) отвечает по SSH, но tinyproxy не установлен,
  порт 8888 никто не слушает;
- документированный 193.233.174.4:22 не отвечает (SSH timeout).

**Причина:** мёртвый прокси + отключённый VPN на локальной машине.

**Решение (2026-09-30):** `OPENAI_PROXY` убран из `.env`, LLM-контур
работает напрямую с рабочим `OPENAI_API_KEY` (при включённом VPN).
Проверено живым вызовом `extract()`: `source=llm`, `llm_error=None`,
`budget_rub=9 000 000` (regex это поле не извлекал), confidence 0.9,
эталон 100%. Regex-fallback остаётся страховкой: VPN/сеть падает →
пайплайн не останавливается. LLM-прогон golden set снова возможен.

## Методика метрик golden set исправлена (2026-09-28)

Раньше TP ставился на любую пару непустых значений, без сравнения строк.
Precision около 1.00 по бюджету и площади была фиктивной.
Сейчас TP только при `exp == got`. Честный regex-baseline: `budget_rub` 0.00 / 0.00.

Дополнение (2026-09-30): телефон сравнивается по цифрам
(`+7 916 123-45-67` == `+79161234567`). До этого LLM-прогон давал
`phone` 0.00 — артефакт форматирования: LLM возвращает телефон
с разделителями, эталон — сплошными цифрами, номера при этом
одинаковые. Проверено живым вызовом `extract()`. Неверный номер
метрика по-прежнему ловит: цифры другие → совпадения нет.

## Черновик ответа клиенту при temperature 0.7 — в roadmap

Чеклист просит отдельный шаг генерации текста при 0.7–0.9.
`utils.chat_json` жёстко `temperature=0.2` (извлечение / классификация).
Фиктивный второй вызов при 0.2 на защиту не выносим: это честнее.
План: параметр temperature в `chat_json` + модуль `extraction/draft_reply.py`.

## Regex не эскалирует по confidence=0.3 (сознательное отклонение)

Чеклист требует: `confidence=low → escalate=true`. В проде:

- **LLM-канал** (`source=llm`): confidence < 0.6 → эскалация.
- **Regex-канал** (`source=regex`): не эскалируем по confidence — у канала
  всегда 0.3, иначе каждая fallback-сделка уходила бы к менеджеру.

Вместо этого для обоих каналов: `etalon_score < 30` → `insufficient_data`
→ мягкая эскалация (intent=qualify, escalate=true, next_action: уточнить поля).

Это правило, а не шум: regex-fallback в 71% случаев извлекает корректные
поля, эскалировать каждую regex-сделку — снижать пропускную способность.

LLM-падение (невалидный JSON / схема / сеть / timeout) → `llm_failed`, даже
если regex собрал карточку. Полный провал LLM+regex → HTTP 200 и безопасный
envelope, не 500.

## POST /ingest не создаёт строку в deals (сознательно)

Чеклист 4) Действие: выбрать один выход — SQLite. `POST /ingest` пишет
в `audit_log` (`deal_id=None`), но не создаёт карточку в `deals`, потому
что нет менеджера и overrides. Карточка появляется через форму CRM.

Это соответствует требованию: таблица результатов — `audit_log`,
`deals` — рабочее место менеджера, не обязательный выход ingest.

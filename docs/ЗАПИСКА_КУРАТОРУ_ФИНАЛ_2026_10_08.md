## 2. Инструкция запуска

**README.md:** https://github.com/PavelKarikoff/OfferDesk/blob/main/README.md

Разделы:

- **Установка и запуск** — `pip install -r requirements.txt`, `python3 app.py`;
- **Переменные окружения** — таблица (`OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_PROXY`, `SECRET_KEY`, `FLASK_API_TOKEN`);
- **Примеры curl** — 3 команды (`/capture`, `/tasks`, `/tasks/extract`);
- **База данных и аудит** — `web_app/deals.db`, таблицы `items` + `audit_runs`;
- **Как воспроизвести ручную проверку** — 2 теста (`noise_01.txt`, `bad_01.txt`);
- **`.env.example`** — файл в корне репо.

**Примеры curl (3 команды):**

```bash
# 1. Создать сущность
curl -X POST http://127.0.0.1:5001/capture \
     -H "Content-Type: application/json" \
     -d '{"text": "Позвонить Сергею завтра в 10:00"}'

# 2. Витрина
curl -s "http://127.0.0.1:5001/tasks?status=open"

# 3. ИИ-обработка (без записи в БД)
curl -X POST http://127.0.0.1:5001/tasks/extract \
     -H "Content-Type: application/json" \
     -d '{"text": "Идея: сделать AI-квалификатор ИЖС"}'
```

**Где лежит база:**

Путь: `web_app/deals.db`.

Просмотр: `sqlite3 web_app/deals.db` → `SELECT * FROM items;` и `SELECT * FROM audit_runs;`.

В веб-панели: `/journal` (журнал `audit_runs`), `/tasks/<id>` (карточка с сырым JSON).

**Как воспроизвести ручную проверку:**

```bash
# Шумный ввод
curl -X POST http://127.0.0.1:5001/capture \
     -H "Content-Type: application/json" \
     -d '{"text": "Аааа, всё горит, надо что-то делать"}'

# Плохой ввод
curl -X POST http://127.0.0.1:5001/capture \
     -H "Content-Type: application/json" \
     -d '{"text": "сделай важное"}'
```

Ожидаемо: `needs_review=true`, `review_reason="AMBIGUOUS_INPUT"`. Метка видна в `/tasks?status=needs_review`.

**`.env.example`:** https://github.com/PavelKarikoff/OfferDesk/blob/main/.env.example

## 5. Доказательства работоспособности

`audit_runs` — запись для каждого ключевого действия:

| Endpoint | action | Пример |
|---|---|---|
| `POST /capture` | `capture` | `(id, 'capture', 'llm', 'success', 2264)` |
| `POST /tasks/extract` | `extract` | Без записи в БД (только ответ) |
| `POST /tasks/<id>/review` | `review` | Снятие `needs_review` |

Скриншоты (`docs/screenshots/tasks/`):

- [`capture.png`](screenshots/tasks/capture.png) — форма + последние 5 (`source=llm`, `needs_review=false`);
- [`list.png`](screenshots/tasks/list.png) — витрина с красными бейджами `needs_review`;
- [`review.png`](screenshots/tasks/review.png) — правка item; карточка `/tasks/<id>` показывает сырой JSON, `action=capture`, `duration_ms`;
- [`journal.png`](screenshots/tasks/journal.png) — `audit_runs` со `source=llm` / `heuristic`, `status=success` / `needs_review`.

Видео `docs/video_demo.mp4` в репозиторий не вложено.

Экспорт JSON:

```bash
curl -s "http://127.0.0.1:5001/tasks?format=json" | python3 -m json.tool
```

или через SQLite:

```bash
sqlite3 -json web_app/deals.db "SELECT * FROM items;"
sqlite3 -json web_app/deals.db "SELECT * FROM audit_runs;"
```

## 6. Отчёт

Отчёт по шаблону: https://github.com/PavelKarikoff/OfferDesk/blob/main/docs/Отчет_выпускной_финал_2026_10_08.md

Все разделы заполнены:

- Название проекта — Вариант 1 (Personal Assistant) + доработка OfferDesk;
- Ценность — для кого и зачем;
- 3 сценария пользователя — создание, витрина, ручная проверка;
- Команды сервиса (API) — 3 ключевые точки + дополнительные;
- Схема данных — 6 таблиц с полями;
- ИИ-операция — схема JSON, temperature 0.2, 4 причины `needs_review`;
- Контроль качества — валидация на входе/выходе, контур отказа, метрики golden set (100% exact);
- Мини-экономика — ~35 000 ₽ на 100 операциях, окупаемость 1 неделя — 1 месяц;
- Риски и меры — 7 штук;
- План развития — 9 пунктов.

Принцип

Разделение ответственности

LLM структурирует

DealExtraction — JSON Schema + Pydantic

  • бюджет, площадь, срок, участок
  • финансирование, материал, контакты
  • sentiment / tone / objections
  • confidence по полям

Температура извлечения 0.2. Модель не ставит цену и не выбирает next_action.

Код решает

validate → escalate → score → action

  • intent — quote / qualify / escalate / reject
  • priority — low / medium / high
  • next_action — что делать менеджеру
  • escalate — bool, считает код

Envelope собирается поверх схемы. LLM не может переопределить маршрут.

priority и escalate считает код, не LLM. Модель не может «замолчать» юридический риск или провал валидации.

Честно

Ограничения и что мы честно признаём

Сейчас: LLM v1

OpenAI доступен напрямую, промпт v1. Golden set — 93.3% exact (14/15), живой прогон 30.09. Regex — не основной режим.

Контур отказа

Если API недоступен → regex fallback, 53.3% exact. Процесс не падает, в audit_log пишется llm_failed.

Таймаут

timeout=35, max_retries=0 → APITimeoutError → fallback за 35 сек, процесс не падает.

Regex confidence

Не эскалируем по confidence=0.3 — шум канала. Мало данных: etalon<30 → insufficient_data.

Цена не у LLM

Модель только структурирует. Цена и юридическая ответственность — у менеджера и прайса компании.

Creative-шаг

Черновик ответа 0.7–0.9 — roadmap. Сейчас chat_json фиксирован на 0.2: температура извлечения, не текста.

Один код, три режима: llm / regex / merged.
